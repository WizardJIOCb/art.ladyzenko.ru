# art.ladyzenko.ru

Два исходных лендинга и отдельная анимированная версия в одном статическом сайте:

| Адрес | Исходная версия | Файлы проекта |
| --- | --- | --- |
| https://art.ladyzenko.ru/ | `C:\Projects\DeepSeek\Test-1` — основная версия | `public/index.html`, `public/assets/` |
| https://art.ladyzenko.ru/new/ | `C:\Projects\DeepSeek\paint-landing` — предыдущая главная | `public/new/index.html`, `public/new/css/`, `public/new/js/` |
| https://art.ladyzenko.ru/new2/ | Копия основной версии с эффектом сборки | `public/new2/` |

На `/new2/` цветные курсоры размечают и собирают блоки при прокрутке,
заголовки появляются по буквам, картины раскрываются, карточки встают на место.
Самостоятельная реализация идеи https://califa.github.io/swarm-site/ на обычном DOM
и Canvas 2D, без копирования кода примера и без дополнительных зависимостей.
Кнопка «Показать всё» завершает эффект, кнопка повтора запускает сборку с начала.
Каждый блок собирается один раз. В фоне анимация приостанавливается, после сборки
видимых блоков цикл отрисовки останавливается. При `prefers-reduced-motion: reduce`,
отключённом JavaScript или недоступном Canvas содержимое отображается сразу.
Тексты, ссылки и формы остаются настоящими HTML-элементами. Основная и прежняя версии поменяны местами по запросу владельца; `/new2/` сохраняет анимацию.

Исходные каталоги сохранены без изменений. В общий проект перенесены только
публичные HTML, CSS, JS и изображения; служебные плагины, логи и снимки не публикуются.
В подвале каждой версии есть ссылка на другую. Для `/new` сервер добавляет
завершающий `/`, сохраняя параметры запроса, чтобы относительные ресурсы
и изображения галереи работали корректно. Отсутствующие страницы возвращают 404.

## Локальный просмотр и проверка

Node.js 22+ и Python 3; установка npm-зависимостей не нужна.

```powershell
py -3 -m http.server 8765 --bind 127.0.0.1 --directory public
npm run check
npm run smoke
```

`check` проверяет локальные ссылки и якоря. `smoke` запускает отдельный
headless Chrome, проверяет три страницы на 1440 и 390 px, меню, галереи,
слайдер основной версии, ошибки JS и ответы ресурсов. Для `/new2/` дополнительно
проверяются сборка при прокрутке, набор заголовка, остановка, повторный запуск,
уменьшение движения и режим без JavaScript. Снимки пишутся в `shots/`.
Путь к Chrome можно задать переменной `CHROME_PATH`.

Проверка опубликованного сайта:

```powershell
node tools/smoke.mjs https://art.ladyzenko.ru
```

## Размещение

Сервер: `82.146.42.213`, SSH alias `myserver`.
Каталог: `/var/www/art.ladyzenko.ru`.
Nginx раздаёт только `current`, который указывает на `releases/<commit>/public`.
Исходники, инструменты и Git недоступны через веб.

После коммита и отправки в GitHub:

```powershell
$revision = git rev-parse HEAD
git archive --format=tar.gz --output=.scratch/release.tar.gz HEAD public server deploy
scp .scratch/release.tar.gz myserver:/tmp/art-ladyzenko-release.tar.gz
scp deploy/release.sh myserver:/tmp/art-ladyzenko-release.sh
ssh myserver "bash /tmp/art-ladyzenko-release.sh $revision /tmp/art-ladyzenko-release.tar.gz"
```

Перед первым выпуском сертификата проверить публичную A-запись домена
через `1.1.1.1` и `8.8.8.8`, отсутствие конфликтующей AAAA-записи.
Скрипт сохраняет конфигурацию Nginx в `/var/backups/art.ladyzenko.ru/<UTC>/`,
переключает символьную ссылку, проверяет Nginx и применяет конфигурацию.
При первом запуске проверяет публичный HTTP ACME webroot и выпускает сертификат
Let's Encrypt. Продление использует системный `certbot.timer` и существующий
deploy hook перезагрузки Nginx. Старые релизы сохраняются для отката.

## Приём заявок

Все формы отправляют `POST /api/leads`. Сервер `server/leads.py` использует стандартную
библиотеку Python 3, слушает только `127.0.0.1:8330`, публичный путь проксирует Nginx.
Заявка сохраняется в SQLite до ответа посетителю и доставляется обоим получателям через
существующий `@anytin_sadik_reposter_bot`. Существующие настройки webhook бота не меняются.

- systemd: `art-ladyzenko-leads.service`;
- закрытая конфигурация бота и получателей: `/etc/art-ladyzenko-leads.json`, режим `0600`;
- systemd передаёт её сервису через `LoadCredential`, файл отсутствует в Git и веб-каталоге;
- база и очередь: `/var/lib/art-ladyzenko-leads/leads.sqlite3`, каталог `0700`;
- локальная диагностика: `http://127.0.0.1:8330/healthz`;
- сообщение включает имя, контакт, направление, комментарий, страницу и ID заявки.

Повтор запроса с тем же ID не дублирует сообщения. Доставка каждому получателю учитывается
отдельно. Явный отказ Telegram с временной ошибкой повторяется с задержкой; неопределённый
результат сетевого сбоя или остановки в момент отправки помечается `uncertain` и не отправляется
вслепую повторно. Такие записи и `failed` требуют проверки оператором. Заявка при этом
остаётся в базе. Не выводить содержимое базы и конфигурации в публичные логи.

Фронтенд сохраняет введённые данные при ошибке, показывает настоящее подтверждение сервера,
использует один ID при повторе и ограничивает повторные клики. Сервер проверяет Origin,
размер и поля, скрытую ловушку спама, ограничивает частоту запросов. Прямые ссылки телефона
и Telegram остаются доступными.

```powershell
npm run test:server
npm run smoke
```

Проверки сервера используют подставной транспорт и не отправляют сообщения людям.
Браузерный smoke подменяет только `/api/leads`, проверяя ошибку, сохранение данных,
повтор с тем же ID и успешное подтверждение во всех версиях. Настоящую контрольную заявку
отправлять отдельно, один раз, с явной пометкой «Тест»; затем проверять `sent` для обоих
получателей в очереди и message ID от Telegram.
